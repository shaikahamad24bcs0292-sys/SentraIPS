# PHASE 5 — RAG + EVIDENCE + REPORT GENERATION

## Objective

Continue from Phase 4.

Build the explainability and reporting layer.

The goal is:

```text
Security finding
      ↓
Relevant NIST/RFC evidence
      ↓
Evidence-linked recommendation
      ↓
LLM explanation
      ↓
Technical + Executive report
```

The IPsecIQ design specifically proposes RAG over standards such as NIST SP 800-77 Rev. 1, RFC 7296, RFC 4301 and RFC 8221.

## Knowledge base

Create:

```text
knowledge_base/
├── nist/
└── rfc/
```

Use the relevant standards documents that are legally/technically appropriate to store and process.

At minimum target:

```text
NIST SP 800-77 Rev. 1
RFC 7296
RFC 4301
RFC 8221
```

Do not invent standards passages.

## RAG pipeline

Implement:

```text
Finding
 ↓
Query generation
 ↓
Relevant evidence retrieval
 ↓
Evidence attached to finding
```

Use a simple vector store.

Do not overcomplicate the first implementation with multiple agents.

Create a structured object:

}

## LLM

* explain findings
* summarize results
* generate recommendations
* create executive/technical language

The LLM must NOT:

* calculate risk
* invent packet information
* invent findings
* override deterministic rules
* invent references

Provide structured findings to the LLM.
